# 市区町村レイヤ 収集設計（Phase 3）

作成日: 2026-07-11 ／ ステータス: 設計たたき台

国＋47都道府県（Phase 1-2）の上に、**市区町村の独自・上乗せ補助**を重ねるためのレイヤ設計。介護施設の実務では「国＋県＋市の3階建て」を合算して初めて手残りが見えるため、ここの取りこぼしが支援価値を左右する。

## 1. スコープと優先順位（カバー人口で切る）

全1,741市区町村を一度に狙わず、**カバー人口の大きい順**に段階収集する。

| Tier | 対象 | 数 | 狙い |
|---|---|---|---|
| Tier 1 | 政令指定都市 + 東京23特別区 | 43 | 最小コストで全国人口の約3割をカバー |
| Tier 2 | 中核市 | 62 | 主要地方都市。県と別枠の上乗せが出やすい |
| Tier 3 | その他市（施行時特例市・一般市） | 約700 | 事業所数の多い市から |
| Tier 4 | 町村 | 約900 | 独自補助は少。県事業でカバーされる前提で後回し |

Tier 1 の43自治体を初期シードとする（下記シードリスト）。

## 2. 重層構造モデル（国 → 県 → 市の上乗せ）

補助金は「併用可否」で合算できる/できないが決まる。制度データに**リレーション属性**を持たせる。

```
制度レコード
├─ 実施主体レベル: 国 / 都道府県 / 市区町村
├─ カバー地域: 全国 / 県コード / 市区町村コード
├─ 財源: 地域医療介護総合確保基金 / 単独財源 / 交付金 ...
├─ 上乗せ元制度ID: (この制度が上乗せする親制度。無ければnull)
├─ 併用可否フラグ: 併用可 / 併用不可 / 要確認
└─ 適用エリア判定: 施設所在地の市区町村コードで自動フィルタ
```

- UIの適合度マッチングは、施設の**市区町村コード**で「国（全国）＋県（該当県）＋市（該当市）」を自動的に束ねて提示する。
- 「上乗せ元制度ID」で親子を結び、詳細ページに **国◯万＋県◯万＋市◯万＝合計◯万** の積み上げを表示できる。

## 3. データソースと収集方式

1. **各自治体の介護保険課/高齢福祉課ページ**（一次情報）… 「介護 補助金」「介護ロボット」「ICT」「生産性向上」で内部検索 → 要綱PDF/募集ページを取得
2. **補助金一覧ページ**（自治体によっては横断ページあり）
3. **集約メディア**（裏取り・発見の補助。一次情報リンクの発見に使い、数値は必ず一次で確認）

取得HTML/PDF → **Claudeで構造化抽出** → `機器マスタ.csv`/`シノニム辞書.csv` で対象機器を正規化 → 制度スキーマに格納。サイト個別パーサは書かず、抽出プロンプト＋スキーマで横展開する。

## 4. 収集スキーマ拡張（市区町村用の追加フィールド）

既存の制度スキーマに以下を追加：

| フィールド | 例 | 用途 |
|---|---|---|
| 市区町村コード | 13109（品川区） | エリア自動フィルタの主キー |
| 上乗せ元制度ID | S-001 | 国/県事業への上乗せ関係 |
| 併用可否 | 併用可 | 合算提示の可否 |
| 財源 | 市単独 / 基金 | 継続性・確度の判断材料 |
| 要綱PDF_URL | .../youkou.pdf | エビデンス直結 |
| 担当課・連絡先 | 高齢福祉課 03-... | 窓口導線 |

## 5. 変更検知・更新頻度

- 1日1回クロール。取得本文の**ハッシュ照合**で差分検知 → 変更時のみ再抽出・更新ログ記録。
- 締切7日前以内の制度は**高頻度（1日複数回）**で締切・受付状況を再確認。
- 「予告」段階（未定）の制度は公開検知したら通知フラグを立てる。

## 6. 品質・ガバナンス

- 数値は**必ず一次情報（要綱PDF/公式ページ）に直結**。集約メディア由来は `確度=中` 止まりとし、一次確認で `高` に昇格。
- 取得日時・出典URL・本文ハッシュを各レコードに保持（サイトの信頼性表示に使用）。
- 抽出の自信度が低い項目は `要確認` として人手レビュー対象キューに回す。

2. 重層提示（国＋県＋市の合算）をUI詳細ページに実装
3. Tier 2（中核市62）へ拡大、以降 Tier 3

## 9. Tier 3 設計（一般市 約700・2026-07-12 追記）

Tier1/2 の全数調査（105自治体・独自13＝約12%）で得た実勢に基づき、**Tier3 は全数台帳を作らない**。理由: (a) 一般市は「広域型施設の補助者」構造が適用されず（施設整備系の補助者は県）、独自制度率はTier1/2よりさらに低い見込み。(b) 700市の全数調査はコスト対効果が悪く、誤って「独自なし」を確定させるリスクもある。

代わりに **検知駆動（discovery-driven）** の3チャネルで拾う:

1. **検索スイープ（月次）**: 「{市名} 介護ロボット 補助金」型のクエリを人口上位から機械的に回し、市公式ドメイン（city.*.lg.jp / city.*.jp）ヒットのみ候補化。集約メディア（補助金ポータル等）のヒットは発見シグナルとして使い、必ず市公式で裏取り。
2. **県ページの市町村言及検出**: 県の要綱・Q&Aに「市町村独自の上乗せ」への言及があれば、該当県の市町村を重点スイープ。
3. **利用者からの報告動線**: ポータルに「この制度が載っていない」報告フォーム（将来）。支援者ネットワークが最強の検知網になる。

発見したら Tier1/2 と同じ流れ（市公式ページ確認 → 制度リスト_市区町村.csv に確度中で追加 → 一次確認で高へ）。**発見済みシード**: 戸田市（介護ロボット等導入支援・市公式ページ確認→M-14登録済）／東広島市（集約メディアに独自補助の記載あり・市公式ページは県事業案内のみ確認→要裏取り。市公式の独自ページが特定できるまで制度リストには載せない）。

台帳は `市区町村シード_Tier3発見.csv`（発見分のみ記録・全数リストなし）を必要になった時点で作成する。
